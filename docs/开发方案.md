# NODO 开发方案

2026-11-16 第一版。

## 一、总体原则

1. **不改 Odoo 核心代码。** NODO 的所有功能都写成独立模块，放在 `addons/` 下。升级时只迁移自己的模块，也符合 LGPL 的边界。
2. **锁定版本。** Odoo 社区版 20.0，镜像 `odoo:20.0-20261112`；数据库 PostgreSQL 16.16。至少一年内不跨大版本。
3. **界面沿用 Odoo 网页端，换成 NODO 品牌和配色。** 只有标准界面没有、又最影响体验的三个页面自己做：角色首页、车间平板终端、排产看板（OWL 组件）。
4. **已有的直接用。** 单据讨论、@提及、关注人、待办活动、附件、操作记录，每张单据都自带。
5. **不含 ERP 财务模块。** 员工档案沿用标准员工管理。先建立档案，再按确认过的职责关联或开通登录账号。

## 二、模块

| 模块 | 基于哪部分标准功能 | 要自己开发的 |
|---|---|---|
| `nodo_base`（必装） | 公司、用户、权限组、中文 | NODO 品牌（标志、配色、登录页、去掉 Odoo 字样和外链）、八类角色（销售、核算、批准、技术、采购、生产、车间操作、质检）、中文打印字体 |
| `nodo_staff_import` | 员工、部门、岗位、文件导入 | 以公司和人员编号预检及导入档案，记录批次，可关联已有内部账号 |
| NODO CRM | CRM（线索、商机）、联系人 | 询盘来源渠道（微信、电话、邮件、上门、老客户返单）、图纸资料归档、跟进提醒 |
| NODO Contract | 销售（报价单、销售订单） | 首批接入单柜选型、原计价服务、版本批准、客户 PDF / Excel、客户确认登记和转单。完整备案字段、未成交管理、合同台账和技术交接分步实施 |
| NODO Supply | 采购、库存 | 员工采购权限、规格核对、采购申请、长周期物料标记、到货跟踪、板材按材质和尺寸管理 |
| NODO MES | 制造（物料清单、生产订单、工作中心、工序） | 钣金工序模板（下料、折弯、焊接、喷涂、装配接线）、缺料不能开工、车间平板报工终端、排产看板 |
| NODO QMS | 库存批次和序列号 | 检验点、检验单、不合格品处理、返工、质量追溯 |
| NODO Draw（技术工作台） | 销售附件清单版本 | 开发库已内置 AE 单开门、双开门设计、附件装配、开孔与出图。京能 0.57.3 原版三维视口使用 Three.js 和 three-mesh-bvh，与二维孔位编辑共用板面基准。销售通过交接接口接入 |
| 报价软件对接 | 销售 | 首批单柜调用原报价服务。并柜、图纸自动识别和后续交接另行规划 |
| 钉钉对接（后期） | 标准第三方登录 | 扫码登录，待审批和被退回推送到钉钉工作通知 |

模块单独可装：每个业务模块只依赖 `nodo_base` 和它用到的标准应用，对应「模块可单独选购，工厂分步上线」。

## 三、技术路线

- 运行：Docker Compose，开发环境项目名 `nodo-dev`，只绑定 `127.0.0.1`。
- 中文 PDF：官方 20.0 镜像已带 Noto CJK 字体，但默认按日文字形回退。NODO 镜像设定 `FC_LANG=zh-cn`，保证打印使用简体中文字形。
- 审批：自研轻量模块，规则是所有报价都须批准。不依赖企业版或第三方模块（OCA 的模块跟进新版本通常要几个月）。
- 多公司：从第一天起支持，每张业务表都带所属公司和记录规则。
- 外部接口：JSON-2（`/json/2/<model>/<method>`）。XML-RPC 和 JSON-RPC 已计划在 Odoo 22 移除，不使用。
- 测试：标准测试框架，测试标签 `nodo`。每个模块带虚构的钣金演示数据，只在测试库加载。

## 四、阶段

时间按一个人加 AI 编程工具全职推进粗估，实际以每阶段验收为准。每个阶段结束都在本公司（钣金企业，试点单位）实际跑一遍，验收通过再进入下一阶段。

| 阶段 | 内容 | 验收标准 | 预估 |
|---|---|---|---|
| 0 工程底座 | 仓库、Docker、中文字体、`nodo_base`（品牌、配色、角色、中文）、AGENTS.md、DESIGN.md、测试框架 | NODO 品牌的中文界面；八个角色可分配；中文 PDF 正常 | 1–2 周 |
| 1 询盘到订单 | NODO CRM、NODO Contract：询盘 → 报价备案 → 核算 → 批准 → 发出 → 成交转订单；销售首页；对客报价文件 | 先用脱敏单柜按原报价逐项对账，再开展内部试用 | 3–4 周 |
| 2 订单到生产 | 技术交接、钣金工序模板、生产订单、NODO Supply（采购申请 → 下单 → 到货）、缺料控制、车间平板报工、排产看板 | 试点一条产线，工人用平板报工 | 4–5 周 |
| 3 质量 | NODO QMS：检验点、质检、不合格品、返工、追溯 | 完工必须质检通过才能交付 | 2–3 周 |
| 4 上线准备 | 导入真实客户、物料、工艺数据；权限复核；自动备份；部署到公司内网服务器；培训和用户指南 | 全公司试用 | 2–3 周 |
| 5 扩展 | 报价软件扩展接入、连接销售与技术工作台、钉钉通知 | — | 另行规划 |

### 阶段 0 任务

| 任务 | 内容 |
|---|---|
| P0-1 | 把本机预览环境移到 `_preview/` |
| P0-2 | 建仓库和项目文档 |
| P0-3 | NODO 开发环境：Dockerfile（简体中文字形）、Compose、配置生成、`scripts/nodo.ps1`、开发库 `nodo_dev` |
| P0-4 | `nodo_base`：品牌、主题变量、角色组和测试用户 |
| P0-5 | 自动化测试、中文 PDF 和界面截图验收 |

### 阶段 2 采购协作

- 首批在 `nodo_supply` 实现员工个人权限和采购单协作。采购助理录草稿，负责技术人员核对规格，采购经理或采购最终确认。先用虚构资料验收，步骤见 [采购协作权限验收](验收/采购协作权限验收.md)。
- 后续将采购入库确认按分管仓库授权。排产看板接入后，由指定销售统一安排本公司订单。

### 阶段 4 上线准备

- 核对正式人员编号、部门路径和岗位，在确定的独立试点库中分批导入已复核的员工档案。账号开通和岗位授权分别确认。开发库用虚构名单，操作见 [人员档案接入](手册/管理员/人员档案接入.md)。
- 内网聊天试点使用固定域名和员工浏览器信任的 HTTPS 证书。反向代理需支持 WebSocket；Odoo 配置多进程时将 `/websocket` 转到 Gevent 端口。
- 纯内网可以在页面开着时使用未读计数、实时收件和消息提示。关页推送另外依赖浏览器的推送中继，列入试点前的联网和送达验收。配置、实测范围和验收步骤见 [聊天部署前提](聊天部署前提.md)。
- 用不同角色的账号走完 [聊天功能验收清单](验收/聊天功能验收清单.md)，确认普通员工与管理员的权限和消息表现。

## 六、许可

- Odoo 社区版为 LGPLv3。自研模块可以用专有许可，修改 LGPL 代码的部分必须公开，所以不复制核心文件来改。
- 企业版代码不可使用和再分发，不引用企业版模块。
- 产品名和界面不使用 Odoo 名称和标志，产品内保留开源组件及许可证说明。
- 正式对外销售前请律师确认许可和商标问题。
