# NODO Contract 原报价服务接入

NODO Contract 继承标准 `sale.order` 和 `sale.order.line`。规则来源为京能原版提交 `c3c120987925ec1b4f417f6c3d398b7f7ce9e6ce` 的单柜路径。组件选择、匹配、预检、双轨计价和原核算的字段口径沿用这条路径。成本与对客文件分别从内部计价快照和对客快照读取。

## 开发环境配置

1. 在约定的开发环境安装 `nodo_contract`。仓库命令为 `scripts/nodo.ps1 install nodo_contract`。若环境同时装有标准销售库存联动，`nodo_contract_stock` 随依赖自动安装。它只暂缓 NODO 单柜订单的自动补货。
2. 准备同版本的原规则目录。需包含 `scheme2_ui.py`、`attachment_v2_client.py`、`freight_state.py` 及其计价依赖，自动生成配置备注还需 `quote_configuration_remark.py`。原计价工作进程会从这个目录运行规则，目录用组织授权的副本。
3. 准备当前公司已授权的原计价隔离环境。服务须能登录、读取产品及 V2 附件目录、预检附件、执行 `/api/quotes/calculate-dual` 和登出。按公司设置字符串系统参数 `nodo_contract.pricing.config.<公司ID>`，值为运行进程可读的本机 JSON 文件绝对路径。Docker 内填写只读挂载后的容器路径。规则目录也须能从该进程访问。

```json
{
  "api_url": "https://pricing.example.invalid/api/quotes/calculate-dual",
  "rules_dir": "/path/to/original-rules",
  "account": "<授权核算测试账号>",
  "api_key": "<授权测试密钥>"
}
```

将配置和凭据留在授权环境的本机目录，限制为应用运行账号和维护人员可读。仓库中只保存配置说明。正式服务 URL 及凭据按组织授权取得。

## 产品与版本

- 在产品的「原报价目录映射」页配置柜体系列，产品基础计量单位按台维护。实际价格库需要型号或变体时，明确填写，尤其是 JC 的豪华型与标配型。附件填原目录中的名称及分类，匹配需要时在单据行录入型号和实测尺寸。
- `models/sale_order.py` 负责核算、批准、客户确认及转单的岗位和阶段检查。`services/quote_price.py` 负责原服务请求并调用 `original_worker.py`。原规则、目录版本、请求与响应进入核算快照。
- `report/customer_quote.xml` 和 `controllers/customer_quote.py` 使用同一份批准版本对客快照。报价行用原规则返回的单价，标准销售行的折扣字段为零。含税、未税金额按单据税种和口径展示。
