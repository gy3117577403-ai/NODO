# 技术工作台的清单交接和本机计算

适用本机开发库 `nodo_dev`，核对日期为 2026-11-20。

## 销售交接

销售端准备好一条柜体订单明细后，可用有交接权限账号的 JSON-2 凭据调用 `POST /json/2/nodo.draw.design/handoff_bom`。技术端读取当前公司的权限上下文。每条明细、每个销售版本对应一份不可覆盖的输入。完全相同的交接重复提交会返回同一个设计编号。原单数量、规格或附件有变化时提交新来源版本。

```json
{
  "payload": {
    "source": "AE-202",
    "source_version": "1",
    "title": "双门配电箱",
    "kind": "double",
    "width": 1000,
    "height": 700,
    "depth": 300,
    "quantity": 1,
    "lines": [
      {"code": "T5-55", "quantity": 1, "face": "door_right"}
    ]
  }
}
```

返回 `design_id` 和 `source`。宽、高、深均为毫米，顶层数量为柜体台数，行数量为每台用量。缺省柜型、规格可由技术补定。销售交接、技术设计、文件下载分别校验权限。设计记录保留接单时的附件库版本，技术修改生成独立批次。多人同时打开同一设计时，旧编辑版本保存会要求重新载入。

## 本机开发库

在项目目录运行以下命令。首次准备工程资源时，用本机已核对的 0.57.3 安装包 `resources/app` 实际绝对路径替换第一条命令的参数。脚本用白名单复制程序、模板、参考图和附件资料到 NODO 私有目录，生成逐文件 SHA-256 清单。图纸、任务、凭据及该私有资源目录不加入 Git。启动计算时使用已安装的 ODA File Converter 27.1 和本机缓存的 cadgen 0.7.26。

```powershell
python scripts/draw/prepare.py "<0.57.3 安装包 resources/app 的绝对路径>"
python scripts/draw/prepare_reference.py "<含单双门原图归档的 0.57.3 resources/app 的绝对路径>"
.\scripts\nodo.ps1 up
.\scripts\nodo.ps1 install nodo_draw
.\scripts\nodo.ps1 draw-start
.\scripts\nodo.ps1 seed-draw
```

升级模块使用 `scripts/nodo.ps1 update nodo_draw`。`seed-draw` 在开发库按基础原图尺寸准备 AE-101 单开门和 AE-202 双开门，附件清单为空，按来源版本幂等。服务端模块测试单独从 `samples.json` 读取装配样例。NODO 浏览器端通过已登录会话提交设计。工程计算在本机独立进程中运行，通过专用目录交换任务，计算进程没有网络监听端口。单开门含外置附件时，基于导出 STEP 的独立外廓核对原图六视图，保留原生柜体宽高深、孔位引线、明细表和图框核对。

附件目录包括 T5-55 固定 STEP、参数化防尘罩、底座、圆锁及 AE-SQ35 方锁。T 形板来自 hasecilu 的 FreeCAD-library 参考模型，原资产署名和 CC BY 3.0 许可随含该模型的图包保存。AE-303 交接版 2 使用四种附件。方锁 STEP 来自京能的闭锁包络生成器，参数及固定 SHA-256 资产保存在 `addons/nodo_draw/data/hardware/`。装配时核对文件摘要。方锁的模型版本 2 在单门原锁位复用 21.2 mm 方孔，改变锁位后按附件的开孔模板校核加工。移动到已有孔或缺口时工程校核可能拒绝。

### 材料与板厚

界面和服务端用 `addons/nodo_draw/data/` 下的 `materials.json` 与 `sheet-rules.json`。两份规则与私有计算资源中的京能 0.57.3 规则逐字节一致。`materials` 和 `thickness` 同时保存分组设定和独立零件覆盖值，随预览、出图任务进入版本快照。加强件默认取原图厚度。新交接设计使用京能默认材料，历史设计读取各自已存的板材和板厚。

浏览器验证分组跟随、零件覆盖、恢复跟随和重新打开。对实际下载件使用 STEP 截面测厚、DWG 与清单回读核对。[交付与回读步骤](../../验收/53-技术工作台紧凑布局与材料板面.md)

### 三维视口

打开技术工作台时，本机才加载 `nodo_draw.assets_ae`。视口使用京能 0.57.3 原始的 Viewer、OrbitControls、间接索引 BVH 点选及 locateFace 板面坐标换算。NODO 负责模型和孔位表单的生命周期。源版本固定为 `cf8681fcf38e282f2fb2b8aa0c6a96ba5d96af24`。前端资源已随模块提供，浏览器打开柜体时无需访问外网。

「零件」从基础预览的 `parts` 读取零件编号、名称与图号，使用同一视口的零件高亮、相机定位和显隐。选中和隐藏保存在当前前端工作区，切换柜型或设计时清空。顶栏「装配」使用完整设计预览，沿用 BOM 匹配与保存入口。

顶栏「三维开孔」启用模型点选和京能孔位控制器。构建脚本在固定版本的 Viewer 上扩展点选回调。射线使用实际门板变换，同时核对可加工板面、可见实体和原图开口，避免穿过现有孔误选后板。U/V 与二维共用板面原点和草稿。确认后由原 CAD 计算流程执行切除，并在同版导出 STEP、DWG、DXF 和孔位表。[三维开孔验收](../../验收/59-三维开孔.md)

需要重建视口时，运行以下命令。第一个路径内须能读取该提交，第二个路径是包含锁定版本 node_modules 的工程根目录。构建脚本核对各依赖版本、许可和两份工程 JSON 的 Git 对象摘要。

```powershell
node scripts/draw/viewer/build.cjs "<京能源码仓库>" "<京能依赖根目录>"
.\scripts\nodo.ps1 update nodo_draw
```

计算进程代码更新后，在队列空闲时运行 `scripts/nodo.ps1 draw-start refresh`。发起装配与开孔的浏览器验收只允许在 `nodo_dev` 执行。[同网格、开孔和五金核对记录](../../验收/50-技术工作台三维预览.md)

### 柜型切换的草稿预览

选择单门或双门时，工作台将当前草稿交给原 CAD 预览引擎。同柜型的无附件柜体预览保留自定义孔，未保存的柜型切换预览按该柜型的基础结构计算。进入「装配」使用完整设计参数，从「三维开孔」或「二维」接续加工时沿用原模型。任务按发起人和公司限制读取，独立于已保存设计和出图版本。相同计算参数可复用最近的草稿任务。切换柜型、设计或预览范围时会放弃旧请求的接收。服务端仍按设计编辑号校验显式保存。[基础柜和模型切换验收](../../验收/60-基础柜与开孔联动.md)

### 基础柜体原图

原图准备脚本从京能 0.57.3 的单双门标准资源复制原始 DWG 和对应矢量预览，逐张核对归档 SHA-256。图纸发布到 `.nodo-draw/exchange/reference/`，由技术岗位会话读取。单门原图规格为宽 380、高 300、深 210 mm，双门为宽 1000、高 700、深 300 mm。出图按实际柜型、规格、材料、板厚、附件和孔位匹配原图或已有批次。原图准备和阅览可独立于 CAD 计算服务进行。

### 历史出图阅图

柜体设计工具栏通过 Owl `Portal` 挂载到应用导航预留位，打开工作台时由这一栏接管柜体选择、出图和视图切换。应用名称及子菜单在该工具栏出现时隐藏。离开工作台后，挂载随工作台销毁，显示当前应用的导航。版本、菜单和草稿仍使用当前工作台实例的状态。

图纸和只读三维按所选出图任务的 ID 读取 SVG 和 `mesh.json`，工具栏「下载」中的 DWG、切割 DXF 和清单指向同一任务。切版会卸载上一批视口并中止旧三维请求，归档视图也就能独立于当前草稿的预览任务。图纸的临时缩放和位置按出图任务及图纸保存。文件复用原有登录和公司记录权限。

使用已登录开发库的技术测试会话和现有 Playwright 环境，运行 `node scripts/draw/verify_archive.cjs`。脚本从页面切换批次、放大、拖动，并核对显示和下载与归档文件摘要一致。实测证据见[历史阅图与同版三维验收](../../验收/52-图纸阅图与同版三维.md)。

操作见[柜体设计与出图](../技术/柜体设计与出图.md)。下载件的独立回读步骤见[工程验收记录](../../验收/49-技术工作台.md)。
