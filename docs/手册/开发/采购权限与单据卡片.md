# 采购权限与单据卡片

2026-11-17 · Odoo 20.0-20261112 · NODO 采购实现基线 `f9c910a`。员工操作见[采购与技术协作](../员工/采购与技术协作.md)，岗位授权由[权限矩阵](../../权限矩阵.md)维护。

## 模块和原生入口

| 模块 | 职责 |
|---|---|
| `nodo_base` | 基础角色、内部讨论、单据卡片和站内分享服务。 |
| `nodo_base_purchase` | `purchase.order` 卡片及标准采购单表单上的「发到聊天」。基础模块和采购都安装后自动安装。 |
| `nodo_supply` | 采购协作菜单和表单、岗位权限、个人开关、技术核对。依赖 `nodo_base_purchase` 与 `purchase_stock`，显式安装。 |

原生单据模型为 `purchase.order` 与 `purchase.order.line`，复用原生单步确认及生成关联收货单。查看 20.0 对应实现时，从本机只读参考路径 `_preview/.native-client-build/payload/server/odoo/addons/purchase` 和 `purchase_stock` 定位。

## 权限链路与改动入口

| 要调整的内容 | 代码 |
|---|---|
| 岗位组和默认能力 | [采购岗位 XML](../../../addons/nodo_supply/security/purchase_roles.xml)、[员工权限模型](../../../addons/nodo_supply/models/res_users.py#L40) |
| 个人开关、生效来源和变更记录 | [用户表单](../../../addons/nodo_supply/views/res_users_views.xml)、[用户写入和记录变更](../../../addons/nodo_supply/models/res_users.py#L87) |
| 采购单范围、草稿写入、技术核对和确认 | [采购单模型](../../../addons/nodo_supply/models/purchase_order.py#L40)、[明细约束](../../../addons/nodo_supply/models/purchase_order_line.py) |
| 查价、报表和打印 | [金额字段权限](../../../addons/nodo_supply/models/purchase_price.py)、[采购报表权限](../../../addons/nodo_supply/models/purchase_reports.py) |
| 采购列表、表单和缓存 | [采购协作视图](../../../addons/nodo_supply/views/purchase_order_views.xml)、[菜单可见性](../../../addons/nodo_supply/models/ir_ui_menu.py)、[采购视图加载](../../../addons/nodo_supply/static/src/js/purchase_views.js) |
| 卡片、选单和分享 | [采购卡片](../../../addons/nodo_base_purchase/models/purchase_order.py#L17)、[通用讨论单据服务](../../../addons/nodo_base/models/discuss_record.py#L53) |

1. **先算用户可用操作，再查单据范围。** 用户设置为 `inherit`、`allow` 或 `deny`。兼岗默认取并集，显式个人值优先。基础查看关闭时关联操作失效。采购单通过 Odoo 20 的 `_access_domain` 收紧公司、本人草稿和技术分派范围，明细继承对应采购单的约束。
2. **业务动作检查人和状态。** `action_nodo_review_specs` 核对操作人是否为负责技术人员、单据是否待确认以及是否有采购明细，然后写入核对人和时间。相关规格字段变更时清除原核对。确认动作检查个人最终确认权限与可读范围，再调用标准采购动作。员工表单上的直接写入限于能编辑的草稿及允许的字段。
3. **查价覆盖各种读取方式。** 采购单和明细的价格字段通过 `has_field_access` 与 `check_field_access` 控制，分析和打印有额外入口检查。前端取得的视图只包含当前可读字段。采购视图跳过原生磁盘视图缓存以在重新打开时应用最新授权。
4. **聊天按接收人的身份读卡片。** `get_record_cards(references)` 用当前用户读取单据，引用格式见[开发笔记的单据卡片部分](../../开发笔记.md#讨论单据卡片与分享t3)。采购卡片按字段权限决定是否拼金额。分享服务检查发送者的单据读取和会话发言权限，消息写入站内链接和附言。接收者打开会话后独立取自己的卡片数据。

## 接手核对

在 NODO 工作区运行项目脚本。一次性库用于代码回归，`nodo_dev` 用虚构资料走浏览器流程。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\nodo.ps1 test nodo_supply
powershell -ExecutionPolicy Bypass -File scripts\nodo.ps1 test nodo_base_purchase
```

采购范围或字段权限有变化时，核对本人草稿和转单后的读权限、技术跨单据访问、兼岗与个人覆盖、价格字段和卡片。涉及原生确认时，核对收货单关联。对应案例见[采购权限测试](../../../addons/nodo_supply/tests/test_purchase_permissions.py)。

改采购 UI 时，同一提交更新受影响的[员工步骤](../员工/采购与技术协作.md)、[管理员步骤](../管理员/采购权限配置.md)及截图，并按本轮角色走受影响路径。修复记录时注明实际触发动作和验证结果。[界面交互核对](../../验收/手册首版交互核对.md)
