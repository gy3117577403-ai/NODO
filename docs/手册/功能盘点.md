2026-11-17 · 开发库 `nodo_dev`。本轮用 Chrome 157 核对代表路径，通过管理员会话读取模块安装状态。以仓库锁定的 Odoo 20.0-20261112 为基础。

| 功能 | 来源与证据 | 适用人员 | 使用入口 |

| 添加成员与开通账号 | 「员工 → 管理」保存后直接进入名单。账号在员工详情的设置中单独开通 | 具有员工建档权限的系统管理员 | [添加成员](管理员/人员档案接入.md#添加成员) |
| 柜体设计与出图 | 开发库用两份 AE 附件清单核对选柜、装配、开孔、下载和 CAD 回读 | 技术、系统管理员 | [柜体设计与出图](技术/柜体设计与出图.md) |

## 已安装、待按部门核对的标准应用

| 应用 | 本轮确认 | 补教程前的核对点 |
|---|---|---|
| 联系人（`contacts`） | 已安装 | 哪些岗位可查或维护客户、供应商，哪些字段需要按岗位隐藏 |
| CRM（`crm`） | 已安装 | 线索与商机的交接人、状态和销售的数据范围 |
| 销售（`sale_management`） | 已安装，报价与销售订单已有聊天卡片 | 报价录入到批准的公司流程，核算、批准和销售的实际权限 |
| 标准采购（`purchase`） | 已安装，首版教程已覆盖采购协作采用的单据操作 | 采购申请、供应商资料维护等其他入口的岗位范围 |
| 库存（`stock`） | 已安装 | 仓库主管和管理员的分仓范围、收货确认流程、车间能见的进度 |
| 制造（`mrp`） | 已安装 | 排产、工单和车间报工的入口和职责，指定销售的排产范围 |

角色账号能看到哪些菜单和完成哪些操作，须逐项核对后再写入员工操作页。仓库确认采购入库、销售统一排产、车间报工和质检在对应阶段更新。详见[开发方案](../开发方案.md)和[权限矩阵](../权限矩阵.md)。
