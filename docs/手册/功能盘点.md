# NODO 功能盘点

2026-11-17 · 开发库 `nodo_dev`。本轮用 Chrome 157 核对代表路径，通过管理员会话读取模块安装状态。以仓库锁定的 Odoo 20.0-20261112 为基础。

## 首版教程

| 功能 | 来源与证据 | 适用人员 | 使用入口 |
|---|---|---|---|
| 登录、切换应用、表单保存 | NODO 主题与标准网页操作。本轮从员工应用菜单进入采购协作并保存草稿 | 全员，菜单随岗位和个人权限显示 | [全员入门](员工/全员入门与讨论.md) |
| 私聊、群聊和人员目录 | NODO 讨论 T1。本轮实测按角色和姓名找同事，建群和成员管理沿用专项验收记录 | 内部员工 | [找同事与建群](员工/全员入门与讨论.md#找同事与建群) |
| 频道公告 | NODO 讨论 T2。本轮实测普通员工和批准角色打开同一公告后的输入区 | 内部员工，发布由频道发言权限决定 | [使用频道](员工/全员入门与讨论.md#使用频道) |
| 消息操作与附件 | NODO 讨论 T4。回复、提及、已读、撤回、贴图、文件和上传限制沿用专项验收记录 | 该会话有访问权限的员工 | [发送与管理消息](员工/全员入门与讨论.md#发送与管理消息) |
| 单据卡片和发到聊天 | NODO 讨论 T3 及销售、采购衔接模块。分享步骤沿用专项验收，本轮复核采购助理在确认后取不到该单卡片 | 能读单据且能在目标会话发言的员工 | [在消息里引用单据](员工/全员入门与讨论.md#在消息里引用单据) |
| 消息提醒、通知与免打扰 | NODO 讨论 T5。本轮核对首选项入口，送达和网络条件见专项记录 | 内部员工 | [设置通知](员工/全员入门与讨论.md#设置通知) |
| 草稿、技术核对、采购确认 | `nodo_supply` 复用标准采购单。本轮用虚构资料实走助理、采购和技术路径。采购经理权限见原专项验收 | 采购助理、采购、采购经理、负责技术人员 | [采购与技术协作](员工/采购与技术协作.md) |
| 员工个人权限 | `nodo_supply`。本轮复核五个权限项和生效来源，开关修改与拒绝行为见专项验收 | 系统管理员 | [采购权限配置](管理员/采购权限配置.md) |
| 人员档案接入 | `nodo_staff_import` 复用标准员工档案。在 Chrome 用虚构名单核对预检、首次导入、重复导入和批次记录 | 系统管理员 | [人员档案接入](管理员/人员档案接入.md) |
| 添加成员与开通账号 | 「员工 → 管理」保存后直接进入名单。账号在员工详情的设置中单独开通 | 具有员工建档权限的系统管理员 | [添加成员](管理员/人员档案接入.md#添加成员) |
| 柜体设计与出图 | 开发库用两份 AE 附件清单核对选柜、装配、开孔、下载和 CAD 回读 | 技术、系统管理员 | [柜体设计与出图](技术/柜体设计与出图.md) |

## 已安装、待按部门核对的标准应用

| 应用 | 本轮确认 | 补教程前的核对点 |
|---|---|---|
| 联系人（`contacts`） | 已安装 | 哪些岗位可查或维护客户、供应商，哪些字段需要按岗位隐藏 |
| CRM（`crm`） | 已安装 | 线索与商机的交接人、状态和销售的数据范围 |
| 销售（`sale_management`） | 已安装，报价与销售订单已有聊天卡片 | 报价录入到批准的公司流程，核算、批准和销售的实际权限 |
| 标准采购（`purchase`） | 已安装，首版教程已覆盖采购协作采用的单据操作 | 采购申请、供应商资料维护等其他入口的岗位范围 |
| 库存（`stock`） | 已安装 | 仓库主管和管理员的分仓范围、收货确认流程、车间能见的进度 |
| 制造（`mrp`） | 已安装 | 排产、工单和车间报工的入口和职责，指定销售的排产范围 |

角色账号能看到哪些菜单和完成哪些操作，须逐项核对后再写入员工操作页。仓库确认采购入库、销售统一排产、车间报工和质检在对应阶段更新。详见[开发方案](../开发方案.md)和[权限矩阵](../权限矩阵.md)。
