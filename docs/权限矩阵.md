# NODO 权限矩阵

2026-11-16 第二版：已记录用户对五个待确认问题的决定（见文末），新增「车间操作」角色。

## 原则

1. 八类角色：销售、核算、批准、技术、采购、生产、车间操作、质检。系统管理员沿用 Odoo 自带的管理员组，不算在八类里。
2. 一个人可以同时有多个角色，默认权限取并集。支持个人设置的项目优先采用个人值，「否」覆盖所有岗位授权。
3. 权限和状态校验在服务端做，界面隐藏不算权限。
4. 多公司：所有角色只能看到自己被授权公司的数据。
5. **实现方式：** `nodo_base` 建立通用角色，各业务模块落实岗位和访问范围。采购协作同时校验岗位默认、个人设置、公司和单据状态。

## 已实现（P0-4）

- 分类「NODO 角色」下八个权限范围，每个范围一个组（技术名 `nodo_base.group_role_*`）：

  | 角色 | 组 | 技术名 |
  |---|---|---|
  | 销售 | 销售人员 | `group_role_sales` |
  | 核算 | 核算员 | `group_role_costing` |
  | 批准 | 审批人 | `group_role_approval` |
  | 技术 | 技术员 | `group_role_engineering` |
  | 采购 | 采购员 | `group_role_purchase` |
  | 生产 | 生产人员 | `group_role_production` |
  | 车间操作 | 操作工 | `group_role_operator` |
  | 质检 | 质检员 | `group_role_quality` |

  用户表单上每个角色单独选择「否」或对应组，一个人可以同时有多个角色。
- 每个角色组只隐含「内部用户」。目前只有角色、没有应用权限的用户能看到：讨论、日历、联系人、仪表板。
- 「车间操作」目前和其他角色一样是内部用户；「只用平板终端、不进后台」在阶段 2 随车间终端一起落实。
- 「应用」菜单改为只对系统管理员可见（上游默认对全部内部用户开放）。
- 开发库 `nodo_dev` 每个角色有一个测试用户 `<角色>@nodo.test`，密码在 `config/dev-accounts.local.md`。

## 采购协作（阶段 2）

| 岗位 | 基础信息与价格 | 录入和修改草稿 | 技术核对 | 最终确认 |
|---|---|---|---|---|
| 采购经理、采购 | 授权公司内的采购单 | 能 | 由负责技术人员操作 | 任一岗位均可 |
| 采购助理 | 本人录入且当前仍为草稿的采购单 | 本人草稿 | 否 | 否 |
| 技术 | 负责人是本人且在授权公司内的采购单 | 否 | 本人负责、待下单的采购单 | 否 |

- 系统管理员在「设置 → 用户 → 个人权限」可覆盖基础查看、查价、录草稿、技术核对和最终确认。选择「岗位默认」恢复继承。打开个人权限时，记录范围仍由公司、草稿录入人或负责技术人员决定。
- 采购经理和采购可在草稿上指定负责技术人员。核对保存员工和时间。修改规格、物料、数量或交期会清除当次核对结果。
- 查价同时控制表单字段、接口、搜索汇总、导出、采购单打印与聊天卡片。关闭基础查看时关联的采购操作也失效。
- 采购经理和采购通过「确认采购单」单步下单，沿用原生采购单和收货单。原生系统管理员入口继续使用公司已配置的审批规则。
- 录单只可选择单据公司可用、启用且具有供应商标记的业务联系人。员工工作联系人从采购单供应商候选中排除。创建、换供应商和确认由服务端校验。
- 核算的查价范围留待该岗位确认。仓库确认采购入库、销售统一排产及车间协作数据范围在各自业务接入时落实。

## 人员档案与岗位

- 系统管理员可以在有权限的公司预检、导入和查看批次记录。人员编号在公司内唯一，仅供系统管理员核对。
- 授权人事可维护可访问公司内员工的岗位。岗位允许补填、更换和清空。分配新岗位时，服务端检查岗位所属公司、部门和在用状态。普通员工按通讯录权限查看。
- 档案岗位用于人员归属。系统管理员管理登录账号，按已确认的职责在关联用户页分配业务角色。保存岗位变更时保留已有账号和授权。

## 内部聊天频道（T2）

| 频道 | 自动加入 | 发言权限 |
|---|---|---|
| 全员通知 | 全体内部员工 | 系统管理员、批准角色 |
| 销售报价 | 销售、核算、批准 | 可访问频道的内部员工 |
| 生产协调 | 技术、采购、生产、车间操作、质检 | 可访问频道的内部员工 |
| 管理员 | 系统管理员 | 仅系统管理员可访问和发言 |

- 三个业务频道在首次安装时配置。系统管理员可以改名、删除或调整发言设置，升级 `nodo_base` 保留这些调整。
- 自动加入沿用 Odoo 的权限组订阅。新增角色会补齐成员关系。移除角色会撤销该角色授予的发言权限，原生订阅关系需要从频道列表执行「离开」或由管理员移除。
- 只有系统管理员权限组（`base.group_system`）可以新建和删除频道、设置发言权限。内部员工可以发起私聊和创建群聊。
- 「仅指定人员可发言」关闭时使用频道的常规发言规则，开启时须属于任一「可发言权限组」。频道的可见范围使用上游「授权组」设置，表情回应继续使用消息读取权限。
- 启用员工讨论接入后，在可访问的频道内按当前公司查找在用内部账号。候选同时须符合频道的授权组，已有频道成员从候选中移除。点击「添加到频道」时服务端再次校验发起人和所选同事。群聊查找与添加使用已有成员权限。「管理员」沿用系统管理员授权组。

## 符号

- **建**：可新建和修改
- **改**：只能修改已有记录（如填写核算结果）
- **读**：只能查看
- **批**：可批准或驳回
- **—**：看不到
- 范围：「本人」指自己负责或创建的记录，「全部」指本公司全部记录

## NODO Contract 单柜报价

首批模块的权限定义如下，待按岗位实测。[单柜报价验收](验收/NODO单柜报价验收.md)

| 岗位 | 单柜报价和阶段操作 |
|---|---|
| 销售 | 建立和修改本人选型草稿、提交核算和批准、查看对客金额和已批准文件、登记发出及客户确认 |
| 核算 | 查看所在公司的单柜报价、修改计价参数、计算、读取成本及利润明细、提交批准 |
| 批准 | 查看所在公司的单柜报价、成本与历史版本，批准或退回，客户确认后确认销售订单 |
| 系统管理员 | 在已授权公司内执行流程管理和维护产品目录映射 |

单据、选型附件和报价版本按公司隔离。批准按报价版本执行，退回后的新版本重新批准。销售访问对客字段，报价版本中的成本、利润和原计价响应仅向核算、批准与系统管理员开放。表中其他部门的合同台账读取属于后续阶段。

单柜选型使用原生「销售 → 报价单」菜单。销售只写本人且处于待选型阶段的图纸与配置，核算和批准读取有权读取的报价原图与识别结果。图纸、识别项目和附件均沿用订单所属公司和记录范围。

局部智能补读由报价所属公司的销售在待选型阶段提交并逐项确认。核算和批准按现有权限查阅补读证据和复核决定。模型凭据及待处理选区图像供服务端配置与任务读取。

## 技术工作台

本机开发库于 2026-11-19 增加技术工作台权限。销售、技术及系统管理员可向当前公司交接附件清单。技术及系统管理员可打开有权访问公司的柜体设计、保存参数、装配、生成与下载成果。应用入口和数据操作均校验岗位，设计和各版文件遵守公司记录规则。销售交接接口只返回设计编号与来源编号。
