# NODO 权限矩阵（草案）

2026-11-16 第一版，待用户确认。标「待确认」的格子需要用户拍板。

## 原则

1. 七类角色：销售、核算、批准、技术、采购、生产、质检。系统管理员沿用 Odoo 自带的管理员组，不算在七类里。
2. 一个人可以同时有多个角色，权限取并集。
3. 权限和状态校验在服务端做，界面隐藏不算权限。
4. 多公司：所有角色只能看到自己被授权公司的数据。
5. **实现方式：** `nodo_base` 只建立「NODO 角色」分类和七个组，不授予任何应用权限，避免依赖全部应用。各应用的权限由对应阶段的模块通过 implied 组和访问规则落实。阶段 0 验收角色存在、可在用户表单勾选，按角色显示的菜单从阶段 1 起验收。

## 已实现（P0-4）

- 分类「NODO 角色」下七个权限范围（销售、核算、批准、技术、采购、生产、质检），每个范围一个组：销售人员、核算员、审批人、技术员、采购员、生产人员、质检员（技术名 `nodo_base.group_role_*`）。用户表单上每个角色单独选择「否」或对应组，一个人可以同时有多个角色。
- 每个角色组只隐含「内部用户」。目前只有角色、没有应用权限的用户能看到：讨论、日历、联系人、仪表板。
- 「应用」菜单改为只对系统管理员可见（上游默认对全部内部用户开放）。
- 开发库 `nodo_dev` 有七个测试用户 `<角色>@nodo.test`，密码在 `config/dev-accounts.local.md`。

## 符号

- **建**：可新建和修改
- **改**：只能修改已有记录（如填写核算结果）
- **读**：只能查看
- **批**：可批准或驳回
- **—**：看不到
- 范围：「本人」指自己负责或创建的记录，「全部」指本公司全部记录
