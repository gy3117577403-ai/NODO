# NODO 聊天部署前提

依据项目锁定的 Odoo `20.0-20261112` 源码和 Windows Chrome 157 本机核对。本文的「开页」包含后台标签页仍运行的情况。「关页」指关闭所有 NODO 标签页，浏览器和操作系统仍具备后台推送能力。

## 环境对照

普通 HTTP 用 `http://nodo-internal.test:8079` 实测。仅在本次 Chrome 进程里把该域名解析到 `127.0.0.1`。浏览器把该网址视为普通 HTTP（`isSecureContext=false`）。该方式验证了浏览器的地址判定及同源连接，实际内网 IP 的路由与其他员工机器的连通性未验证。

## 关页推送需要什么

1. **源码确认**。网页通过 `/web/service-worker.js` 注册脚本。员工设备授予站点通知权限后，浏览器通过 Push API 取得订阅地址与加密参数，Odoo 将当前登录账号的订阅登记到 `mail.push.device`。新域名、新浏览器或新浏览器配置各自授权和订阅。
2. **源码确认**。Odoo 首次需要时生成数据库级 VAPID 公钥与私钥，存于 `mail.web_push_vapid_public_key` 和 `mail.web_push_vapid_private_key`。服务器向浏览器订阅返回的推送端点发送加密 HTTPS 请求。VAPID 使用 `web.base.url` 作为站点标识，试点应设为正式内网 HTTPS 地址。多人推送还会使用 Web Push 定时任务处理队列。VAPID 由 Odoo 自行管理。
3. **源码确认**。浏览器供应商提供推送端点。服务器需要能通过 DNS 和 HTTPS 到达已登记的端点，终端浏览器也要能连接其推送服务。纯内网无法完成关页送达。已经订阅的设备后台桌面通知优先交给原生推送，若中继不可达，实时收件与未读计数仍然更新，后台桌面通知可能收不到。未接入中继的设备可在页面保持连接时使用本地桌面通知。

对应源码位于 `addons/mail/models/mail_push_device.py`、`addons/mail/models/mail_thread.py`、`addons/mail/models/mail_push.py`、`addons/mail/tools/web_push.py`、`addons/mail/static/src/webclient/web/webclient.js` 和 `addons/mail/static/src/service_worker.js`。

## 多进程与反向代理

- **源码确认**。开发环境默认 `workers=0`，网页与 WebSocket 进入同一 HTTP 端口（容器 8069）。开发机的 8079 只绑定回环。
- **源码确认**。Linux 部署用 `workers > 0` 时，普通页面、接口、静态资源和 `/web/service-worker.js` 走普通 HTTP（默认 8069）。精确的 `/websocket` 路径及查询参数转发到 `gevent_port`（默认 8072）。将 WebSocket 交给普通 HTTP worker 时，Odoo 会报未连上 evented port。配置反向代理到 WebSocket 上游使用 HTTP/1.1，并传递 `Upgrade` 和 `Connection: upgrade`，保留长连接。
- **源码确认**。在受信任代理后启用 `proxy_mode = True`。由代理写入 `X-Forwarded-Host`、`X-Forwarded-Proto`、`X-Forwarded-For`。客户端通过 HTTPS 打开站点时，前端按同一地址发起 `wss://`。应用端口供代理使用。

相关实现见 `odoo/service/server.py`、`odoo/tools/config.py`、`odoo/http/router.py`、`addons/bus/controllers/websocket.py` 和 `addons/bus/static/src/services/bus_plugin.js`。

## 试点做法和待验证项

建议用固定内网域名、终端信任的 HTTPS 证书及支持 WebSocket 的反向代理。普通 HTTP 可试用页面内提醒、实时聊天和键盘粘贴。内网页面需要 HTTPS 才能启用系统桌面通知和关页推送；关页推送还取决于外部中继是否可达。

- **未验证**实际内网域名及证书。由 IT 提供可用站点后，在员工终端检查 `isSecureContext`，确认 `/websocket` 握手返回 101。双账号核对前台收件、后台桌面通知和点通知返回会话。
- **未验证**多进程代理链路。试点启用预定的 `workers` 配置后，核对 `/websocket` 到 Gevent 端口、登录和静态资源到普通 HTTP 端口，验证长时间空闲后仍可收件。
- **未验证**关闭 NODO 标签后的到达与点击。用获准联网的试点设备授权通知，核对订阅登记和推送队列，再关闭所有 NODO 标签，用另一账号发消息，确认系统收到并可点开目标会话。纯内网试点将该项列为不可用。
