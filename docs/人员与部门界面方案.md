# 人员与部门界面方案

此页供确认界面方向。人员试点库使用标准「员工」应用查看档案。这一版用 125 份虚构档案预览新版界面与交互。

## 界面样稿

在浏览器打开 [员工模块 HTML](设计预览/员工模块/index.html)。样稿使用仓库已有的 NODO 字标、图标字体和材质颜色。

- [员工目录截图](设计预览/员工模块/30-员工模块-01-员工目录.png)展示部门树、名单、搜索和复核筛选。
- [员工详情和个人权限截图](设计预览/员工模块/30-员工模块-02-员工详情与权限.png)展示名单保留在左侧时的档案、账号及权限入口。
- [生产计划部门截图](设计预览/员工模块/30-员工模块-03-生产计划部门结构.png)展示仓库、车间和直接归属员工。

Chrome 核对了姓名与编号搜索、部门和岗位联合筛选、分页、详情三页切换、权限预览、档案复核及窄屏使用。样稿中的编辑和权限切换在当前页面内生效。正式导入跳转至 NODO 设置中的原有入口。

## 首页

保留「员工」应用入口，默认打开员工列表。左边按架构图保留公司、部门和下级组，右边显示选定部门及下级的人员。部门数值按当前可见档案计算。顶部可按姓名、正式人员编号或岗位搜索，管理员可以快速筛选「待复核」「缺岗位」「未开通」。

```text
员工                         搜索姓名、编号或岗位      导入人员
┌ 部门 ──────────┬ 员工列表 ──────────────────────────────────────┐
│ 全部部门       │ 姓名    部门    岗位    档案状态    登录账号    │
│ ▾ 生产计划部   │ ……      ……      ……      待复核      未开通      │
│   仓库         │                                                 │
│   车间         │ 筛选  待复核 · 缺岗位 · 未开通                   │
└────────────────┴─────────────────────────────────────────────────┘
```

默认展开常用分支，样稿默认打开总经办与生产计划部。选部门时保留搜索词和筛选，点「全部部门」仍可沿用当前筛选。同名人员可按部门、岗位和人员编号区分。缺少岗位或正式编号的档案显示「待填写」，来源编号放在管理员的核对区。

进入「部门」后，右侧单独列出下级组和本部门直接归属的员工，汇总包含两部分。点「查看员工」保留部门范围并进入名单。

## 员工详情

| 区域 | 信息和动作 |
|---|---|
| 档案 | 姓名、人员编号、部门路径、岗位和来源。管理员可补齐资料并确认复核。 |
| 账号 | 显示未开通、已开通或停用。管理员通过现有用户表单关联账号或开通登录。 |
| 个人权限 | 显示岗位默认、个人设定和当前生效值。采购权限复用已有的「岗位默认」「能」「否」和服务端校验。 |

桌面点击一行打开右侧详情，列表保留选中部门和滚动位置。窄屏用「选择部门」收起部门树，详情使用整页。管理员可在详情继续打开原有员工或用户表单。部门树采用薄面板，列表与详情沿用 NODO 的白色表面和统一选中态，按钮、字段和阴影复用现有变量与 mixin。

## 开发和验收顺序

1. **员工列表与部门树**。核对生产计划部下的仓库和车间能分别查看。同名人员可按部门及岗位区分，搜索和部门筛选可以一起使用。
2. **档案复核**。核对岗位空缺等不完整档案能筛出。补齐正式编号、部门和岗位后可标记「已复核」。点击某一导入批次时可回到待处理的人员。
3. **账号与权限入口**。在员工详情进入已有用户及采购权限配置。用虚构账号检查采购助理、采购、采购经理和负责技术人员的生效范围。仓库入库和销售排产的开关随对应服务端功能提供。

岗位名称、档案复核状态和账号状态分别呈现。管理员手册、操作截图和权限说明随相应页面一起更新。
