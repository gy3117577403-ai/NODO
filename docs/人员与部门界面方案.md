# 人员与部门界面方案

员工目录方案使用 125 份虚构档案预览。开发库和本机人员试点库在「员工 → 管理」使用新版名单和详情。人员试点库读取已导入的组织架构资料，可通过「补充信息」复核员工档案。[试点库入口和核对步骤](手册/管理员/人员档案接入.md#从架构图初始化试点名单)

## 员工自助目录

开发库从「员工 → 目录」进入卡片视图。顶部可按姓名、岗位和工作邮箱查找，结果可与公司、部门筛选叠加。部门名称和管理员名单按同一规则着色，左栏通过缩进显示层级。卡片显示直属部门和上一级部门，完整路径可在员工资料查看。

普通员工通过卡片查看公开资料，右侧「视图」可切换看板、列表和层级。[员工操作手册](手册/员工/全员入门与讨论.md#从员工目录找同事)

## 首页

保留「员工」应用入口，默认打开员工列表。左边按架构图保留公司、部门和下级组，右边显示选定部门及下级的人员。部门数值按当前可见档案计算。顶部可按姓名、正式人员编号或岗位搜索，管理员可以快速筛选「待复核」「缺岗位」「未开通」。

```text
员工                         搜索姓名、编号或岗位      导入人员
┌ 部门 ──────────┬ 员工列表 ──────────────────────────────────────┐
│ 全部部门       │ 姓名    部门    岗位    档案状态    登录账号    │
│ ▾ 生产计划部   │ ……      ……      ……      待复核      未开通      │
│   仓库         │                                                 │
│   车间         │ 筛选  待复核 · 缺岗位 · 未开通                   │
└────────────────┴─────────────────────────────────────────────────┘
```

默认展开常用分支，样稿默认打开总经办与生产计划部。选部门时保留搜索词和筛选，点「全部部门」仍可沿用当前筛选。同名人员可按部门、岗位和人员编号区分。缺少岗位或正式编号的档案显示「待填写」，来源编号放在管理员的核对区。

本机名单沿用组织树的层级和部门名称。总经办用绿色，各部门在树和名单路径中共用自己的颜色。表格按完整部门路径排序，点击「部门」列头切换方向，排序覆盖分页与当前筛选。组长与主管按档案岗位标红。档案和账号状态使用共用的 2.5D 状态键。[员工名单实测](验收/40-员工名单-01-部门名称配色.jpg)

进入「部门」后，右侧单独列出下级组和本部门直接归属的员工，汇总包含两部分。点「查看员工」保留部门范围并进入名单。

### 添加成员

开发库在标准「员工 → 管理」提供实际保存的「添加成员」。页头显示当前结果人数和建档操作，左侧为可收起的部门卡片。名单卡片内放搜索、视图和分页。输入姓名和部门即可建档，人员编号和岗位可稍后补齐。保存后名单刷新，可见的新行短暂高亮。详见[管理员操作步骤](手册/管理员/人员档案接入.md#添加成员)和[本机验收截图](验收/成员添加验收.md)。

## 员工详情

从「员工 → 管理」点击名单中的一行，进入独立的员工详情。有档案编辑权限时可从头像下上传图片。系统管理员在姓名下查看人员编号，复核和账号状态在下一行并排显示。默认「档案」呈现部门、岗位、直属上级和工作联系方式，长部门路径在本列换行。「工作」保留完整的任职编辑入口，「履历」和「个人」保留原有资料。「用工与工时」在有权限的人员选项卡末尾出现。右侧「活动记录」沿用同一员工的消息、备注和活动。账号由系统管理员在「设置 → 登录账号」单独开通。弹窗复用「添加成员」的版式和控件，显示当前员工摘要，填写登录名即可建立并关联内部账号。[档案首屏](验收/38-员工档案-01-头像与任职信息.jpg) · [开通账号弹窗](验收/35-员工账号-01-开通弹窗.png)

点击「关联用户」右侧箭头进入账号页。业务角色按已安装模块的 NODO 权限范围逐项设置，页面显示当前生效角色。「修改密码」打开身份验证和新密码表单。「完整用户设置」提供公司范围、个人权限和其他账户设置。[关联用户页](验收/36-关联用户-01-账号页.png)

授权人事从员工详情的「工作 → 岗位」补填、调整或清空岗位。候选岗位来自员工所属公司和部门，维护步骤见[人事维护岗位](手册/管理员/人员档案接入.md#人事维护岗位)。

界面样稿中的侧栏使用以下内容组织方式。

| 区域 | 信息和动作 |
|---|---|
| 档案 | 姓名、人员编号、部门路径、岗位和来源。管理员可补齐资料并确认复核。 |
| 账号 | 显示未开通、已开通或停用。管理员通过现有用户表单关联账号或开通登录。 |
| 个人权限 | 显示岗位默认、个人设定和当前生效值。采购权限复用已有的「岗位默认」「能」「否」和服务端校验。 |

在样稿中，桌面点击一行打开右侧详情，列表保留选中部门和滚动位置。窄屏用「选择部门」收起部门树，详情使用整页。管理员可在详情继续打开原有员工或用户表单。部门树采用薄面板，列表与详情沿用 NODO 的白色表面和统一选中态，按钮、字段和阴影复用现有变量与 mixin。

### 补充信息

开发库从员工详情档案卡右上角打开「补充信息」。目录样稿支持点击缺项直达相应字段。两处共用一个弹窗。摘要展示头像、姓名、只读的架构图编号和原档案的复核状态。下方单列填写人员编号、部门、岗位，部门列表使用当前可访问的完整路径。

底部提示待补数量，字段填齐后显示「资料已齐」。姓名和部门必填，同公司人员编号查重时忽略字母大小写。保存失败时在原地保留输入，光标移到出错字段。开发库使用员工档案的权限和当前版本，保存资料时保留原复核标签。缺少复核标签的档案显示「暂无复核记录」。

开发库使用虚构档案核对真实保存。设计样稿中的编辑只在当前页面生效。[开发库默认状态](验收/32-员工弹窗-01-默认.png) · [部门选择](验收/32-员工弹窗-02-展开部门.png) · [窄屏校验](验收/32-员工弹窗-03-窄屏校验.png) · [操作演示](验收/32-员工弹窗-04-操作演示.gif)

## 开发和验收顺序

1. **员工列表与部门树**。核对生产计划部下的仓库和车间能分别查看。同名人员可按部门及岗位区分，搜索和部门筛选可以一起使用。
2. **档案复核**。核对岗位空缺等不完整档案能筛出。补齐正式编号、部门和岗位后可标记「已复核」。点击某一导入批次时可回到待处理的人员。
3. **账号与权限入口**。在员工详情进入已有用户及采购权限配置。用虚构账号检查采购助理、采购、采购经理和负责技术人员的生效范围。仓库入库和销售排产的开关随对应服务端功能提供。

岗位名称、档案复核状态和账号状态分别呈现。管理员手册、操作截图和权限说明随相应页面一起更新。
