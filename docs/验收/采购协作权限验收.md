# 采购协作权限验收

在开发库 `nodo_dev` 打开 [NODO 登录](http://127.0.0.1:8079/web/login?db=nodo_dev)。密码存放在本地 `config/dev-accounts.local.md`。不同账号可以用独立的浏览器会话。

| 岗位 | 账号 |
|---|---|
| 系统管理员 | 本地账号文件中的「管理员」一行 |
| 采购助理 | `supply.assistant@nodo.test` |
| 技术核对员 | `supply.engineer@nodo.test` |
| 采购 | `supply.buyer@nodo.test` |
| 采购经理 | `supply.manager@nodo.test` |

1. **采购助理录单。** 打开「采购协作 → 采购单」，新建一张草稿。供应商选「雾岬物资」，明细选「配线标识加工」，填写规格描述、数量和单价。用鼠标离开明细行，点左上角「手动保存」图标，记下单号。助理可看到这张草稿的单价和总金额。
2. **采购分配技术。** 采购或采购经理打开同一张草稿，将「负责技术人员」设为「技术核对员」并保存。技术核对员打开该单，核对规格描述、数量和交期，点击「确认规格已核对」，查看核对人和时间。技术只能打开分派给自己的采购单。
3. **管理员切换个人权限。** 在「设置 → 用户」打开「采购经办」，到「个人权限」将「查看采购价格」和「确认采购单」设为「否」并保存。采购经办刷新该单后仍可读规格和数量，页面省略单价与总金额，也隐藏确认按钮。管理员可在同页查看变更记录。
4. **恢复并下单。** 把两项设回「岗位默认」。采购经办刷新后点击「确认采购单」，查看已下单状态。助理刷新采购单列表，原单已离开本人草稿范围。采购经理可用另一张草稿独立走一遍确认。

浏览器核对使用虚构单据 P00002。截图记录了[助理录单](26-采购权限-01-助理录单.png)、[技术核对](26-采购权限-02-技术核对.png)、[个人权限变更](26-采购权限-03-员工个人权限.png)、[关闭查价与确认](26-采购权限-04-关闭查价与确认.png)和[恢复后确认采购](26-采购权限-05-采购确认.png)。

## 供应商选择验收

- 在开发库用管理员打开「采购」新建询价，用采购助理打开「采购协作」新建草稿。两个入口按匿名员工姓名搜索均无结果。标准表单的「搜索更多」只列当前公司可用的已建档供应商。选择「雾岬物资」后分别保存了虚构草稿 P00006 和 P00007。[员工搜索截图](29-采购供应商-01-采购搜员工无结果.png) · [搜索更多截图](29-采购供应商-02-搜索更多只列供应商.png)
- 使用采购助理会话直接提交员工工作联系人时，服务端返回「请选择已建档的供应商」。`scripts/nodo.ps1 test nodo_supply` 的 17 项全部通过，新增检查覆盖两个表单的搜索范围、空名单、创建和更换供应商、导入，以及停用后的确认和审批。
- 在人员试点库打开新询价，供应商候选为零，显示建档提示。两个库中的 Chrome 核对均为 0 个控制台错误。[空名单截图](29-采购供应商-03-暂无供应商提示.png)

重新准备验收资料时运行下列命令。开发库已安装模块时直接运行第二条。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\nodo.ps1 install nodo_supply
powershell -ExecutionPolicy Bypass -File scripts\nodo.ps1 seed-supply-pilot
```
